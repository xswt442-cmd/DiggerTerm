# DiggerTerm 架构

[English](ARCHITECTURE.en.md) · 简体中文

## 组件与职责

DiggerTerm 是 Go/Wails 3 桌面终端应用，使用 Vue 3/TypeScript 和 xterm.js 展示会话。同一个 Go 程序既能作为 GUI 启动，也能以独立的 `--daemon` 模式启动。

- 根目录 Go 程序：应用入口、资源嵌入、GUI/Daemon 启动选择。
- `frontend/`：终端显示、会话侧栏、分屏、搜索、设置及与 Wails 服务的交互。
- `internal/desktop/`：GUI 暴露给前端的服务、用户设置和 GUI 生命周期，并通过 IPC 调用后台 Daemon。
- `internal/daemon/`：管理会话、系统进程和 IPC 连接，并直接操作 PTY/ConPTY、WSL 和 SSH 客户端。
- `internal/session/`：托管会话的读写、调整大小、输出回放及生命周期。
- `internal/observe/`：扫描并合并外部 Windows/WSL 进程的只读元信息，区分平台来源和进程身份。

## 会话与 IPC 边界

GUI 是 Daemon 的 IPC 客户端。GUI 关闭、隐藏或重新打开时，Daemon 管理的会话可以保持运行并重新连接。Daemon 退出或操作系统重启后，不会保留活跃进程。Daemon 使用当前系统用户专属的本地 IPC，界面不得绕过 Daemon 直接接管进程。

Windows 管理员与普通 GUI 使用不同的 Daemon 端点和会话。管理员命名管道仅允许管理员访问，并在通信两端验证对方的用户身份和提权状态。

快速 CD 按 PowerShell、CMD 或 POSIX Shell 的规则转义选定路径，生成 `cd` 命令。用户点击后，命令通过托管终端已有的输入通道排队发送，并补一个回车。使用前须确认当前 Shell 提示符为空。快速 CD 不会直接修改其他进程的工作目录，只有本机绝对路径可以设为新建本地会话的默认目录。Dig 观察到的外部进程没有快速 CD 入口。

本机文件夹通过 Wails 3 原生目录对话框选择，无需 Daemon 参与。Windows 盘符路径会转换为 WSL/Git Bash 默认挂载格式，自定义挂载点需手动输入。

SSH 浏览器使用托管会话记录的目标主机和端口，重命名会话不会改变这两个值。独立的 OpenSSH BatchMode 进程沿用 ssh_config 与主机密钥验证，只读枚举目录。枚举结果以 NUL 分隔，对超时时间、并发数量和结果大小设限，不向会话当前 PTY 发送命令。浏览要求使用密钥或 SSH Agent 免交互认证，且远端 Shell 兼容 POSIX。如果 SSH 目标只支持交互密码登录，或使用非 POSIX Shell，用户仍可手动输入路径。

一个运行中的托管会话同时只有一个 GUI 控制端。输入、窗口尺寸调整和终止操作都由 Daemon 校验请求方是否持有该会话的控制权。其他 GUI 不能终止正在被控制的会话，未被控制的托管会话允许显式终止。关闭面板只分离视图，终端已接收的输入按会话排队，在分离请求之前发送。用户明确要求批量终止时，Daemon 会重新核对目标并执行确认流程。

GUI 的 IPC 请求具有有界超时：普通请求 15 秒、会话创建 30 秒、外部进程扫描 45 秒。超时只表示客户端尚未收到最终响应，Daemon 可能仍在完成操作。创建或终止请求超时后，先重新查询会话状态，再决定是否重试，以免重复提交同一操作。

## 外部观察与平台边界

`Managed` 表示由 Daemon 创建并管理的会话。`Observed` 表示外部终端或 Agent 进程的只读观察结果。外部观察只提供被允许的元信息，不能读取 PTY 画面、注入输入、结束进程或接管会话。

Windows PID 与 WSL 各发行版的 PID 属于不同命名空间。外部父子进程关系可能不完整，界面只把有依据的关系标为推断。Windows ConPTY、WSL、OpenSSH 和 Linux PTY 分别由对应平台的实现提供。

## 专注模式与更新检测

专注模式是 GUI 的显示状态。它保留当前终端和终端内的操作，同时不提供会改变工作区或当前会话的控制入口，也不改变 Daemon 的会话所有权、PTY 状态和 Managed/Observed 边界。

专注模式下，DiggerTerm 不打开自己的终端右键菜单，也不截获终端的键盘、鼠标报告或链接激活事件。DiggerTerm 在进入专注模式前会关闭自己的搜索、快速选择、复制模式、快速 CD 和普通覆盖提示。

GUI 最多每 24 小时通过有界请求检查一次 GitHub 最新稳定版本。更新检测只提供版本状态和下载入口，不会静默下载或安装，也不会终止会话或停止 Daemon。安装新版本仍需用户从公开 Release 资产手动下载并执行。

## 数据与配置

终端布局、主题、快捷键及其他偏好保存在本机用户的配置目录。主题支持用户提供的 JSON 和 CSS 文件，配置文件路径见应用提供的帮助页面或对应代码。公开文档只描述可用的配置结构，不固化某台开发机的私人路径。

## 代码与发布

构建和打包任务定义在 `Taskfile.yml`，CI 工作流在 `.github/workflows/`，本文件不重复列出命令。PR CI 使用 `scripts/check-docs.mjs` 检查文档路径、中英文配对、CHANGELOG 双语分类和当前版本一致性，并校验 PR 模板同步。GitHub Release 的中英文正文从目标 Tag 的 CHANGELOG 生成，具体步骤见 [发布手册](RELEASE.md)。公开文档应描述当前行为与用户限制，不存放单次测试流水或私人环境信息。
